---
description: ソースコードのコメントを日本語化し、標準JSDoc形式に統一する
---

1. 対象ファイルを確認する
   - ユーザーから指定されたファイル、またはディレクトリ内の主要なソースコード（`.ts`, `.tsx`）を特定する。

2. コメントを日本語化・JSDoc化する
   - **AIによる翻訳**: 既存の英語コメントを自然な日本語に翻訳する。直訳ではなく、コードの意図（Why/How）を補足する。
   - **フォーマット統一**:
     - 関数・クラス・インターフェースの上部には `/** ... */` 形式のJSDocブロックを使用する。
     - 単一行コメント `//` は行単位の補足説明に使用する。
     - `@param`, `@returns`, `@throws` などのタグを活用し、型情報だけでなく「どういう時に何が起きるか」を記述する。
   - **例**:
     ```typescript
     /**
      * ユーザーIDに基づいて記事データを取得する。
      * キャッシュが存在する場合はそれを返し、ない場合はDBから取得してキャッシュする。
      *
      * @param userId 対象のユーザーID (UUID形式)
      * @returns 記事オブジェクトの配列。存在しない場合は空配列。
      * @throws {AppError} DB接続エラー時 (code: DB_CONNECTION_FAILED)
      */
     export async function fetchUserArticles(userId: string): Promise<Article[]> { ... }
     ```

3. 既存のJSDocを修正する
   - 既に日本語で書かれている場合も、フォーマットが崩れていたり情報が不足している場合は補完する。
   - 「TODO:」や「FIXME:」などの残骸があれば、解消されているか確認し、削除またはIssue化を提案する。

4. 変更を検証する
   - コードの論理（ロジック）を変更していないことを確認する。コメントのみの変更であることを保証する。
