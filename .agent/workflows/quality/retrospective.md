このワークフローは、AIエージェントとのセッション完了時に実施する「振り返り（レトロスペクティブ）」です。
今回の作業を通じて得られた知見、うまくいった点、改善すべき点を言語化し、次回の開発品質と効率を向上させることを目的とします。

以下のフォーマットに従って、今回のセッションを振り返ってください。

# セッション振り返り (Retrospective)

## 1. 概要 (Summary)

- **タスク:** [今回のタスク内容を簡潔に]
- **結果:** [完了/未完了/一部完了]
- **主な成果物:** [変更したファイル、作成したドキュメントなど]

## 2. KPT (Keep / Problem / Try)

### Keep (良かったこと・続けたいこと)

- [ ] エージェントの振る舞いで助かったこと
- [ ] 効果的だった指示（プロンプト）の仕方
- [ ] 採用して良かった設計や実装パターン

### Problem (課題・うまくいかなかったこと)

- [ ] 手戻りが発生した箇所とその原因
- [ ] エージェントへの指示がうまく伝わらなかった場面
- [ ] 実装上の技術的なハマりポイント

### Try (次回の改善・挑戦したいこと)

- [ ] 次回のエージェントへの指示の改善案
- [ ] ルールファイル (`.agent/rules/*.md`) への追記・修正案
- [ ] ワークフロー (`.agent/workflows/*.md`) の改善案
- [ ] 新たに導入したいツールやライブラリ

## 3. ドキュメント更新と知見の汎用化 (Knowledge Action)

今回の学びを後続の開発やAIエージェントの動きに確実に活かすため、以下のドキュメント更新を**必須アクション**として検討・実行してください。

- [ ] **ルールファイルの更新**: `.agent/rules/*.md` に反省点から得た新しい制約やガイドラインを追加する
- [ ] **ワークフローの改善**: `.agent/workflows/*.md` に抜け漏れを防ぐための確認手順などを追加する
- [ ] **技術ドキュメントの更新**: `README.md` などのシステムドキュメントに、今回判明した明確な仕様（例：共通スキーマの利用方針など）を明記する

## 4. アクションアイテム (Action Items)

- [ ] 次のタスクへの引き継ぎ事項
- [ ] 未解決として残す技術的課題やTODO

---

**エージェントへの指示:**
この振り返り内容をもとに、**必ず** `.agent/rules/`, `.agent/workflows/`, またはソースコード傍の `README.md` のいずれか（あるいは複数）に対して更新を提案し、ファイルの修正内容を提示あるいは直接修正してください。
学びを単なる反省で終わらせず、プロジェクトの仕組みやエージェントの事前知識として定着させるサイクルを回すことが、強力なコーディングアシスタントとしてのあなたの重要な役割です。
