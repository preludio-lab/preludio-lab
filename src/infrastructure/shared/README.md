# Shared インフラストラクチャ (src/infrastructure/shared)

Shared ディレクトリは、リポジトリパターンの実装を簡略化し、一貫性を保つための基底クラスや共通ユーティリティを提供します。

## 基底リポジトリ (`base.repository.ts`)

リポジトリ実装のボイラープレートを削減し、ログ出力やエラーハンドリングを標準化するために、以下の2つの抽象クラスを提供しています。

### 1. BaseMetadataRepository

データベースなどのメタデータのみを扱うリポジトリの基底クラスです。

- **役割**: 単一のデータソース（ `metadataDS` ）に対する CRUD 抽象化。
- **テンプレートメソッド**:
  - `reconstituteMetadata(row)`: DB行からドメインモデルへの変換。
  - `toPersistenceMetadata(entity)`: ドメインモデルからDB行への変換。
- **内部メソッド**: `_findOne`, `_findMany`, `_save`, `_delete` をラップし、一貫したフローを提供します。

### 2. BasePayloadRepository

メタデータ（DB）とペイロード（オブジェクトストレージ）の両方を扱うアグリゲートのための基底クラスです。

- **役割**: DB と ストレージの整合性を確保しながら、アグリゲート全体を永続化・復元します。
- **整合性戦略 (Storage First)**:
  - **保存時**: 最初にオブジェクトストレージに保存し、成功後にのみDBを更新します。DB保存に失敗した場合は、ストレージに保存したファイルを削除（ロールバック）を試みます。
  - **削除時**: 最初にオブジェクトストレージから削除し、成功後にのみDBからレコードを削除します。
- **追加のテンプレートメソッド**:
  - `resolveStorageKey(entity)`: ストレージ上の保存パスを決定。
  - `reconstituteAggregate(base, payload)`: メタデータと本文を結合してアグリゲートを再構築。

## 設定管理 (`config/`)

`infraConfig` を通じて、アプリケーション全体のインフラ構成（メタデータの参照先、ストレージの種別など）を一元管理します。環境変数 `DATABASE_URL` や `R2_BUCKET` などの検証とアクセスを提供します。
