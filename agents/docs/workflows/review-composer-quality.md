# 作曲家マスターデータ品質レビュー（AIエージェント用）ワークフロー

## 目的

AIエージェント（Gemini CLI, Antigravity, etc.）を活用し、生成された作曲家マスターデータが世界最高のクラシック音楽サイトにふさわしい品質であることを多角的に検証します。

## レビューのタイミング

1. **Draft生成直後**: 日本語の内容が音楽史的に正確で、代表作の選定に漏れがないかを確認。
2. **Translate実行直後**: 多言語の翻訳が自然で、各言語のタイポグラフィ基準を満たしているかを確認。

---

## 1. 音楽史・事実関係・構成の検証 (Musicological Accuracy & Structure)

このプロンプトは、特定の作曲家の事実関係および、我々が定義した「ミニマルなサマリー構成」を検証する際に使用します。

### Gemini CLI 用プロンプト

```text
@data/composers/{slug}.json を確認し、以下の項目に事実誤認や違和感がないか、信頼できる音楽辞典（New Grove Dictionary等）の基準で検証してください。

- **事実関係**: 生没日、生誕地、代表作、時代区分 (era) は正確か？
- **代表ジャンルと楽器**: その作曲家の歴史的業績を最も象徴するものか？
- **サマリーの構成 (summary.ja)**: 以下の「ミニマリズム」が徹底されているか？
    1. 専門用語（対位法など）や生没年、冗長な背景が混入していないか？
    2. 「①通称/イメージ」「②一言で伝わる魅力」「③代表作1〜2曲（『』で囲む）」の3要素だけで構成されているか？
- **タグ (tags)**: その人物を端的に表すキーワードとして適切か？
```

---

## 2. 多言語・タイポグラフィ検証 (Multilingual & Typography)

翻訳された `summary` フィールドが各言語のネイティブにとって自然か、他言語が混入していないか、およびタイポグラフィの規則を厳守しているかを検証します。

### Gemini CLI / Antigravity 用プロンプト

```text
@data/composers/{slug}.json の `summary` フィールドについて、各言語のネイティブ・ローカライゼーション専門家としてレビューしてください。

1. **言語の混線 (Language Bleed) の検知【最重要】**:
   フランス語の中にスペイン語の「y」が混ざるなど、他言語の単語や文法が数パーセントでも混入していないか厳格にチェックしてください。
2. **自然な表現と固有名詞**:
   - 翻訳調（直訳）を避け、その言語圏で一般的な雅称を採用しているか？
   - 楽曲の愛称が直訳（例: Fate Symphony）ではなく、現地で最も一般的な呼称（例: Symphony No. 5）になっているか？
3. **タイポグラフィの厳守**:
   - EN: シングルクォート ' ' が使われているか？
   - DE: ドイツ式引用符 „ “ が使われているか？
   - FR / ES: ギュメ « » (特にFRは前後にスペース) が使われているか？
   - ZH: 作品名に書名号 《 》 が使われているか？また、フルネームの中黒はハイフン(-)ではなく、必ず「·」になっているか？
4. **文字数制限**: いずれかの言語で 300 文字（文字数）を超えていないか？（UI崩れ防止）

不適切な箇所があれば、具体的な修正案を `--review` 引数に渡せる形式で提示してください。
```

## 3. 数値・印象評価の妥当性検証 (Impression Dimensions)

`impressionDimensions` が、音楽的な特徴を正しく反映しているかを確認します。

### プロンプト

```text
@data/composers/{slug}.json の `impressionDimensions` (-10から10の数値) を確認してください。
この作曲家の音楽的特徴と比較して、数値の妥当性を分析してください。

※注意: この評価軸は -10 から 10 までのスケールであり、0が中立を意味します。マイナスの値は「劣っている」のではなく「対極の性質（例: theatricalityのマイナスは『絶対音楽的・内省的』）」を意味します。この仕様を理解した上で、極端な数値（±7以上）の妥当性を評価してください。

- **innovation (革新性)**: 後世への影響や形式の破壊/創造の度合い。
- **emotionality (情感)**: ロマン派的な感情表現の強さ。
- **complexity (複雑性)**: 対位法的な緻密さや構造の難解さ。
- **theatricality (劇場性)**: オペラ的、あるいは外向的な派手さ。
```

## 4. レビュー結果の反映方法

レビューで指摘された内容は、以下のコマンドで反映させます。

```bash
pnpm run workflow:composer --slug {slug} --step refine --review "ここにAIからの指摘内容を貼り付ける"
```
