# 作曲家マスターデータ品質レビュー（AIエージェント用）ワークフロー

## 目的

AIエージェント（Gemini CLI, Antigravity, etc.）を活用し、生成された作曲家マスターデータが世界最高のクラシック音楽サイトにふさわしい品質であることを多角的に検証します。

## レビューのタイミング

1. **Draft生成直後**: 日本語の内容が音楽史的に正確で、代表作の選定に漏れがないかを確認。
2. **Translate実行直後**: 多言語の翻訳が自然で、各言語のタイポグラフィ基準を満たしているかを確認。

---

## 1. 音楽史・事実関係の検証プロンプト (Musicological Accuracy)

このプロンプトは、特定の作曲家の事実関係（生没日、生誕地、代表作、時代区分）を検証する際に使用します。

### Gemini CLI 用プロンプト

```text
@data/composers/{slug}.json を確認し、以下の項目に事実誤認や違和感がないか、信頼できる音楽辞典（New Grove Dictionary等）の基準で検証してください。

- **生没日と場所**: 日付は正確か？場所のスラグ名と国コードに矛盾はないか？
- **時代区分 (era)**: 他の作曲家との一貫性が保たれているか？
- **代表ジャンルと楽器**: その作曲家の歴史的業績を最も象徴するものか？
- **タグ (tags)**: その人物を端的に表すキーワードとして適切か？
```

---

## 2. 多言語・タイポグラフィ検証プロンプト (Multilingual & Typography)

翻訳された `summary` フィールドが各言語のネイティブにとって自然で、かつタイポグラフィの規則（引用符、スペース等）に従っているかを検証します。

### Gemini CLI / Antigravity 用プロンプト

```text
@data/composers/{slug}.json の `summary` フィールドについて、各言語のネイティブ・ローカライゼーション専門家としてレビューしてください。

1. **自然な表現**: 翻訳調（直訳）になっていないか？その言語圏で一般的に使われる雅称や表現が採用されているか？
2. **タイポグラフィの厳守**:
   - ドイツ語: 引用符は „ “ になっているか？
   - フランス語・スペイン語: 引用符は « » になっているか？
   - 中国語: 作品名は 《 》 で囲まれているか？
3. **文字数制限**: いずれかの言語で 300 文字（バイト数ではなく文字数）を超えていないか？（UI崩れ防止）

不適切な箇所があれば、具体的な修正案を JSON の形式、または `--review` 引数に渡せる形式で提示してください。
```

---

## 3. 数値・印象評価の妥当性検証 (Impression Dimensions)

`impressionDimensions`（革新性、情感、複雑性など）が、音楽的な特徴を正しく反映しているかを確認します。

### プロンプト

```text
@data/composers/{slug}.json の `impressionDimensions` (-10から10の数値) を確認してください。
この作曲家の音楽的特徴と比較して、以下の数値に違和感はないか分析してください。

- **innovation (革新性)**: 後世への影響や形式の破壊/創造の度合い。
- **emotionality (情感)**: ロマン派的な感情表現の強さ。
- **complexity (複雑性)**: 対位法的な緻密さや構造の難解さ。
- **theatricality (劇場性)**: オペラ的、あるいは外向的な派手さ。

例えば、バッハの complexity は高く、ブラームスの theatricality は低いといった一貫性が保たれている必要があります。
```

---

## 4. レビュー結果の反映方法

レビューで指摘された内容は、以下のコマンドで反映させます。

```bash
pnpm run workflow:composer --slug {slug} --step refine --review "ここにAIからの指摘内容を貼り付ける"
```

翻訳後に発覚した軽微なタイポグラフィ修正（引用符の修正など）は、`finalize` 前に直接ファイルを編集するか、翻訳プロンプトを調整して `translate` を再実行することで対応します。
